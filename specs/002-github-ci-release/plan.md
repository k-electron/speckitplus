# Implementation Plan: GitHub CI & Native Release Automation

**Branch**: `002-github-ci-release` | **Date**: 2026-09-03 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/002-github-ci-release/spec.md`

## Summary

Build a fully automated Continuous Integration (CI) and Continuous Delivery (CD) release pipeline natively in GitHub Actions for SpecKitPlus. The pipeline consists of two dedicated, zero-third-party-action workflows:
1. **`.github/workflows/ci.yml`**: Multi-platform quality gates matrix (Ubuntu Linux & macOS Darwin across Python 3.10–3.13) verifying shell syntax (`bash -n`), contract tests, manifest/lifecycle schemas, and all 8 regression suites on every PR and push to `main`.
2. **`.github/workflows/release.yml`**: Tag-triggered (`v*.*.*`) and manual dispatch release pipeline that executes verification gates, builds a clean `.zip` release archive (`lifecycle-<version>.zip`) with SHA256 checksums, extracts release notes from `CHANGELOG.md`, publishes a tagged GitHub Release via native GitHub CLI (`gh release create`), updates `catalog-submission.json`, and outputs community catalog PR submission instructions to `$GITHUB_STEP_SUMMARY`.

## Technical Context

**Language/Version**: GitHub Actions YAML workflow syntax, POSIX-compliant Bash (compatible with bash 3.2+ on macOS and bash 5+ on Linux), Python 3.10+.

**Primary Dependencies**: GitHub Actions standard virtual environments (`ubuntu-latest`, `macos-latest`), GitHub CLI (`gh`), POSIX utilities (`zip`, `sha256sum`, `shasum`). Strictly zero third-party GitHub Marketplace actions or external npm/pip dependencies.

**Storage**: Filesystem and GitHub Releases. Generated release archives (`lifecycle-<version>.zip` and `lifecycle.zip`) and checksum files (`.sha256`).

**Testing**: Executed directly via GitHub Actions matrix runner:
- Shell static analysis: `bash -n`
- Python compilation: `py_compile`
- Schema conformance: Python `unittest` against `extension-manifest.schema.json` and `lifecycle.schema.json`
- Full regression orchestrator: `./tests/run_all_tests.sh` (8 suites)

**Target Platform**: GitHub Actions CI/CD infrastructure (Ubuntu Linux and macOS runners).

**Project Type**: CI/CD & Distribution Infrastructure for Spec Kit Extension.

**Performance Goals**: CI run completion < 3 minutes; release gate, packaging, and publishing < 2 minutes.

**Constraints**: Fail-closed on any test or schema validation failure. Zero temporary/development files in release archives (`.git`, `__pycache__`, `.DS_Store`). Zero third-party action dependencies (security surface minimization).

**Scale/Scope**: 2 GitHub Actions workflow definitions (`ci.yml`, `release.yml`) and 1 helper packaging script (`scripts/package-release.sh`).

**Structure Decision**:
- Workflows reside in standard `.github/workflows/`.
- A dedicated, testable POSIX packaging script [`scripts/package-release.sh`](scripts/package-release.sh) encapsulates archive bundling, file exclusions, and SHA256 checksum generation so distribution packaging can be tested and verified locally as well as in CI.
- [`scripts/lifecycle-engine.py`](scripts/lifecycle-engine.py) exposes two dedicated CLI subcommands for release workflows:
  - `release-notes <VERSION>`: Parses `CHANGELOG.md` using standard Python string matching, extracting the exact release notes for `## [<VERSION>]` to stdout (exits 0 on match, 1 on missing version). This eliminates brittle POSIX `sed`/`awk` differences between macOS BSD and Linux GNU.
  - `verify-version <VERSION>`: Verifies that the given version strictly matches `extension.version` declared in `extension.yml` and `catalog-submission.json` (exits 0 on success, 1 on divergence).
